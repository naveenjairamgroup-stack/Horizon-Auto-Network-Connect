# Horizon Auto — Network Connect

Dealer network ERP for Horizon Auto (Honda two-wheeler dealer network,
Jharkhand). Tracks vehicle sales, parts supply, commission, outstanding,
credit limit, and inventory value across AD / ASC / FO dealer types.

## Architecture

```
┌─────────────────────┐        HTTPS (POST, JSON)        ┌──────────────────────┐
│  frontend/           │ ───────────────────────────────▶ │  backend/             │
│  Plain HTML/CSS/JS    │ ◀─────────────────────────────── │  Google Apps Script   │
│  Hosted: Cloudflare   │           JSON response          │  Web App API          │
│  Pages (via GitHub)   │                                   │  Data: Google Sheets  │
└─────────────────────┘                                    └──────────────────────┘
```

- **Frontend** is a static single-page app — no build step, no framework,
  just ES modules loaded directly by the browser. Deployed automatically by
  Cloudflare Pages whenever this repo's `frontend/` folder changes (once
  configured — see `docs/DEPLOYMENT_GUIDE.md`).
- **Backend** is unchanged in spirit from before — every business-logic
  function is exactly what it always was — but it's now called over plain
  HTTP JSON instead of `google.script.run`, since the frontend no longer
  lives inside Apps Script's own HtmlService. See `backend/Code.gs` for how
  requests are routed.
- **Database** is still the same Google Sheet; nothing about the data model
  changed.

## Folder structure

```
frontend/
  index.html            ← generated by build.py from pages/*.html — this is what Cloudflare Pages serves
  build.py               ← local dev convenience: regenerates index.html after you edit a page fragment
  pages/                 ← one HTML fragment per screen (source of truth)
  assets/
    css/styles.css
    js/
      config.js          ← BACKEND_URL — update this after every Apps Script redeploy
      api.js             ← fetch() wrapper (replaces google.script.run)
      session.js          ← shared login/session state
      router.js           ← page show/hide + role→dashboard mapping
      sidebar.js           ← builds the left nav per role
      auth.js              ← login / logout
      app.js               ← entry point: wires forms, exposes onclick handlers on window
      pages/                ← one module per screen, mirrors pages/*.html

backend/
  Code.gs               ← entry point + JSON API dispatcher/whitelist
  Config.gs, Setup.gs
  Utils/ Auth/ Audit/ Masters/ Ledger/ Payments/ Returns/
  Commission/ CreditControl/ Dashboard/ Import/
  appsscript.json
  .clasp.json            ← put your Apps Script project's Script ID here

docs/
  DEPLOYMENT_GUIDE.md    ← full setup: clasp push, Apps Script deploy, Cloudflare Pages connect
```

## Quick start (after cloning)

1. **Backend**: see `docs/DEPLOYMENT_GUIDE.md` §Backend — push via `clasp`, deploy as a Web App, copy the `/exec` URL.
2. **Frontend**: paste that URL into `frontend/assets/js/config.js` (`BACKEND_URL`).
3. If you edited anything under `frontend/pages/`, run `python3 frontend/build.py` to regenerate `index.html`.
4. Commit and push — Cloudflare Pages picks it up automatically.

## Adding a new backend function

1. Write the function anywhere under `backend/` as usual (it should call `safeRun(...)` like every existing function does).
2. Add it to the `API_DISPATCH` object in `backend/Code.gs` — this is both the router and the security whitelist; anything not listed there cannot be called from the frontend.
3. Call it from the frontend the same way as everything else: `api('yourFunctionName', session.token, ...)`.
